QUESTION 1

Main Objective & Real-World Problem Solved

❌ The Real-World Problems

  • •
    No Central Security: Clients call microservices directly, exposing internal ports and duplicating login code everywhere.
  • •
    Dumb Load Balancing: Standard systems send traffic to slow or crashing servers without checking their health.
  • •
    Surprise Crashes: Traditional rate limits only react after the server is already down from high traffic.

✔ What Nexus Gateway Does

  • •
    Single Secure Door (:8080): All requests pass through one gateway that verifies JWT tokens before touching services.
  • •
    Smart Health Routing: Gateway checks latency and CPU, automatically routing requests to the fastest server.
  • •
    AI Predictive Defense: Predicts traffic spikes 10 minutes ahead and blocks abusive IPs before servers overload.
QUESTION 2

Why Did You Choose This Specific Tech Stack?

Spring Cloud Gateway

Fast, non-blocking Netty engine. Can handle tens of thousands of requests per second without crashing.

Redis

Ultra-fast in-memory cache. Checks rate limits (100 req/min) in less than 1 millisecond.

Apache Kafka

High-speed event broker. Sends logs in the background without slowing down the user's request.

Python (FastAPI + AI)

Industry standard for machine learning. Runs Random Forest to forecast traffic and catch anomaly attacks.

PostgreSQL (UUIDs)

Reliable SQL database. Uses random UUIDs so hackers cannot guess sequential user IDs.

React 18 Dashboard

Modern live control plane to inspect requests, view AI forecasts, and manage security rules.

QUESTION 3

System Architecture & Data Flow

1. Request User sends API request to port :8080.
2. JWT Check Gateway checks token (blocks if invalid).
3. Rate Limit Redis counts hits (429 if >100 RPM).
4. Smart Route Sends to healthiest replica (User 1 or 2).
5. Async Log Kafka logs event; AI updates forecast.
SMART ROUTING FORMULA:
Health Score = (0.5 × Latency) + (0.3 × CPU Health) + (0.2 × Error Free Rate)
Traffic automatically routes to whichever instance has the highest health score.
QUESTION 4

Major Technical Challenges & How We Fixed Them

Challenge 1: Slow Database Logging

Writing logs straight to the DB slowed requests from 15ms to 1,200ms during load tests.

✔ Solution

Used Apache Kafka to stream logs in the background with zero user wait time.

Challenge 2: Lost User Info in Reactive Gateway

Standard Spring Security lost user details because Netty switches worker threads.

✔ Solution

Extracted JWT claims directly and injected them into downstream request headers.

Challenge 3: UUID Migration Crash

Switching from numeric IDs to UUIDs caused frontend forms to crash with NaN errors.

✔ Solution

Updated backend DTOs to UUID and built user dropdown pickers in the UI.

QUESTION 5

Key Limitations & Future Scope

⚠️ Current Limitations

  • Single Broker: Dev setup uses single Redis and Kafka containers (needs cluster for enterprise scale).
  • AI Cold Start: Model needs 5 minutes of initial traffic logs to learn patterns after a fresh restart.
  • Flat Token Cost: Light requests and heavy database searches both cost 1 rate limit token.

🚀 Future Scope & Roadmap

  • K8s Predictive Auto-scaling: Spin up new server pods before traffic peaks hit using AI forecasts.
  • Zero-Trust Service Mesh (mTLS): Encrypt all internal communication between microservices.
  • Weighted Rate Limiting: Charge more tokens for expensive database queries.
